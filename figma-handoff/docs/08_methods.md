# 08 やり方（実測・比較・評価）

## 1. 写真の明るさをそろえる（ON-RIDE と OFF-RIDE）

1. `get_screenshot` で同じブレークポイントの 2 枚を等倍で取る（PC 1440、TAB 1133 高、SP 844 高）。返ってきた URL を `curl -sL -o name.png <url>` で保存。
2. `python3 scripts/measure_brightness.py off_pc.png on_pc.png ...` で比較。
   - `mean`（平均の明るさ）、`p5/p25/p50/p95`（暗部〜明部の分布）、`std`、`noise`（細かいざらつき）、`blue-red`（青み）。
   - ファイル名の 2 つ目の語（pc/tab/sp）で、文字の範囲をノイズ計算から除く。
3. 文字の下の製品の見え方は「中央の細部」＝中央帯から文字の範囲を除いた標準偏差で見た（OFF：TAB 19.6、PC 11.9）。
4. 試作は本物を変えず、画面外（x=-30000）に clone を作って値を変え、測ってから本物に適用。一時 clone は消す。
- 注意：clone を撮ると原本よりノイズが低く出る（描画の解像度の違い）。ノイズは原本どうしで比べる。

## 2. 原型と原本の画素差分

1. 原本（例 PH2 _ Dark PC `5414:64983`）と複製（`5637:56069`）を同じ `maxDimension` で撮る。
2. numpy で行ごとの平均差を出し、差の大きい行の範囲を元の座標に戻して確認する。
3. 2026-10-14：変数モードを付け直した後、差はピルの静止位置（y9119〜9132）だけ。

## 3. 案の評価（UX カード）

ユーザーの指定：**キーワード＋少しの説明・口語・ユーザー体験中心**。

### 4 軸

| 軸 | 意味 |
|---|---|
| 気づく | 見つけやすいか |
| わかる | 押すと何が起きるか想像できるか |
| ジャマしない | 見たいもの・読みたいものを邪魔しないか |
| 迷わない | PC でも SP でも（ナビでも電話でも）同じ場所・同じ形か |

◎ すごくいい（緑 `#e2f4e7`/`#1d7a3a`）／○ いい（青 `#e7eef8`/`#2b5a9e`）／△ いまいち（橙 `#fdeedb`/`#a35a00`）。前提（例：世代データ）は灰色のタグ。

### カードの中身（幅 1100、白、角丸 20）

1. 案名（Bold 32）
2. ひとこと（1 文、口語）
3. 4 軸のピル（＋前提タグ）
4. いいところ／イマイチ（各 2〜3 個、短く）

### まとめ（幅 2400）
- 題「ひと目でくらべる（使う人目線）」、4 軸の説明 1 行、**結論 3 行**（今ならこれ／条件付きでこれ／別の基準ならこれ）、全案の表（案・4 軸・ひとこと）。

台本の部品は `scripts/ux_cards_builder.js`（`card(P, W)` と `summary(title, rows, verdicts, W)`）。

## 4. 色を建模から取る

- `switch · Gen2` を `get_screenshot` で取り、中心から放射状の帯ごとに中央値を取る（上半分・下半分も分けて）→ 筐体・台座・暗い輪・中央キーの色を決めた（`docs/04_design-specs.md` B）。
