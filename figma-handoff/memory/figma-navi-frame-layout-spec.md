**線を全部やめて「光」に置き換えた（2026-08-13 第3ラウンド・ユーザー指摘）**
指摘＝**「3端点3本線にすると3台とも操作できるように見える。実際に操作できるのはプロトタイプ式だけ」**。線は「つながっている」しか言えず、**「今どれが焦点か」も「どれが押せるか」も表現できない**。[[figma-web68-navi-build]] に記録済みの方針（光に2つの意味を持たせる／環・枠・吹き出しは足さない）が、このフレーム群では未実装だったのが原因。

- **`bus`/`tick`/`node`（PC）と `spine`/`node`（SP）を全削除**。LP 本体に連結線が1本も無いという原生語彙にも戻った
- **状態光＝大きく拡散・静止**：`GRADIENT_RADIAL`（中心 accent@0.20 → 外周 alpha 0）。PC は 900×760、SP は 560×520。**焦点機器の視覚中心に置き、frame の最背面へ**（`insertChild(0, e)`）
  - 色は**その機器固有の accent**＝A01 は phone のマップ青 `#3c8ff3`／C01 はバイクの緑 `#03af7a`。caption の色とも一致する
- **操作光＝キー1個ぶん・中性色・呼吸 2.8s**：`#ffffff@0.30` → 透明の円を **ENT キー（＝switch の中心）** に、switch の直上へ。PC 径 110／SP 径 66。**C案だけに置く**（A案は操作できないので状態光のみ）。ノード名に `key-glow · 操作光（呼吸 2.8s）` と入れてある
- **減光を「1フレームに全開は1台だけ」に統一**。それまでは C-PC が phone と switch 両方 1.0、A-SP が phone と switch 両方 1.0 …と焦点が割れていた。今は **焦点 1.0 ／ 他 0.55**
- **SP の glow は元々どこも指していなかった**（A01 は中心 195,231 に対し phone 中心 110,244／C01 は 195,561 に対し switch 中心 165,662）。焦点機器の視覚中心へ置き直した
- 線を消して空いた caption〜機器間の 109px は、**状態光がちょうど埋める**ので空白に見えない
- SP は spine が消えたので機器を **x=52 → 24**（見出し・caption と左端が揃った）

**HB Switch の透明枠：視覚領域は bbox の 13.24%〜86.76%**（370 枠に face 49..321）。これが効いてくる場面が多い：
- 位置合わせ・間隔の計算は必ず**視覚値**で行う。bbox で「15px しか離れてない」と見えても実際は 59px 空いている
- 視覚中心 = `x + 0.5W`、視覚左 = `x + 0.1324W`、視覚右 = `x + 0.8676W`（縦も同じ）
- SP では **bbox の x を phone/meter に揃えると視覚は 23〜30px 内側に入る**が、視覚で揃えると chevron が spine（x=32）に重なるので **bbox 揃え（x=52）のままにする**
- `rescale()` は screen 系インスタンス（phone/meter）用、`resize()` は HB Switch 用（SCALE constraints 済み）。SP の phone は Frame に包まれているので **instance を rescale したあと Frame も同じ寸法に resize** すること

**「寂しい」を埋める空気の層（2026-08-13 第6ラウンド）**
ユーザーが見出し `ナビゲーション` を全フレームから削除し、SP の caption を上部へ移動した結果、**PC の上 180px・下 140px が完全な空白**になり「寂しい・空」という指摘。**横線の追加は禁止**という条件のもと、線ではなく光と奥行きで埋めた。

- **画像レイヤーの余白は文字レイヤーと別**：文字は版心 144..1296 のまま、**機器は 100..1340（1240幅）** を使う。C系の switch は 380 → **440**（視覚 1016..1340）
- **背後の環境光3層**（[[figma-web68-navi-build]] の Apple 寄り方針をようやく実装）
  - `amb · studio 光` … 1700×760 の楕円 #ffffff@0.055→透明、frame 最背面、x=-130 y=-330。**上半分の空白が「死んだ黒」でなく「光のある空気」になる**。SP は 560×340 @0.05
  - `glow`（機器固有色）… 既存
  - `amb · vignette` … 画面全面の矩形に径向グラデ（中心 a=0 @0.58 → 端 #000@0.30）。**機器の上・文字の下**に挟む。SP は小さいので効きが強すぎ、**@0.18 / position 0.68 まで弱める**
- **`floor-bounce`** … 各機器の真下に扁平楕円（PC 40px高／SP 26px高）。**機器が床に落とす反射光**で「立っている」感を出す。色は機器由来（phone=白、meter/switch=緑）、焦点だけ 0.11〜0.13、非焦点 0.04〜0.05
- **被写界深度**：非焦点に `LAYER_BLUR radius 1`。写真の語彙で奥行きが出る
- **⚠ 減光・ボケ・vignette は掛け算になる**。最初 0.55＋blur1.6＋vignette0.5 でスイッチが消えた。**非焦点は PC 0.62 / SP 0.7 まで戻す**のが下限
- caption の y を A/C で統一（PC 180、SP 52）。ユーザー調整で A=160/C=180、SP は A=49/C=61 とズレていた

**引導と演出（2026-08-13 第7ラウンド）**
「まだ空い」「引導が足りない」という指摘に対し、**装飾ではなく引導そのもので空白を埋める**方針にした。
- **`role · ○○` ラベル**＝各機器が**そのフレームで果たしている役割**を 12px ls4% #ffffff@0.38 で機器の真下に。削除された `SMARTPHONE / BIKE` ラベルが答えられていなかった「この3台は何なのか」に答える
  - **主役には付けない**。主役は caption（A案）か key-hint の accent カプセル（C案）が担う。**形式の違いそのものが「これが操作対象」と言っている**
  - A01: meter『走行情報を表示』／switch『待機中』。C01・C02・C0X: phone『地図を表示中』／meter『結果はここに出る』。C03: phone『同じリストを表示』／switch『次は ▶ に倒す』
- **caption の記号を図形化**：`setRangeFontSize(0, 1, 68)` で先頭の `✓` だけ 68px に。**文案であると同時に押すキーの形**なので、見た瞬間にどれを押すか分かる。C系のみ（A案の caption に記号は無い）
- **押下の余波**：C03 に **C02 と同名の `key-glow · 接触`** を 420×420・`opacity 0.001` で置く。SMART_ANIMATE は同名レイヤーを補間するので、102px@1 → 420px@0 = **キーから広がって消える衝撃波**になる。線を1本も使わずに「信号が伝わった」を表現できる
- **`C00 · 入場（登場アニメ用）` `1731:11195`**（100, 5430）… 3機器を +26y・`opacity 0.001`・`LAYER_BLUR 6`、文字類も透明にした状態。0.25s 後に C01 へ SMART_ANIMATE 0.8s で「浮かび上がって定位置に収まる」。**flow 起点はこれ**
- **背景に画面を巨大ボカシで敷く案は失敗**。meter は黒くて見えず、phone だと**ただの灰色の板**に見えた（blur 64 でも矩形の輪郭が残る）。氾用の「空白埋め」にはならないので採用せず

**「画面に喋らせる」＝セルフデモと焦点リレー（2026-08-13 第8ラウンド）**
ユーザー指示は **「让画面自己去说话」**。よって「3台の機器はこれです」と**文字で説明する序幕フレームは作らず**、[[figma-web68-navi-build]] に既記の方針「0s 呼吸 → 4s セルフデモ1回 → 文字ヒント」を実装する形にした。

- **入場を3段に分割し、機器を信号の順に登場させる**。`C00`（全部透明）→ `C00a · 入場①スマホ` `1732:11317`（100, 6476）→ `C00b · 入場②メーター` `1732:11456`（100, 7522）→ `C01`
- **焦点リレー**：登場した機器が光を持ち、次が来ると退く。**`glow` の x が 188 → 664 → 1178 と移動する**ので SMART_ANIMATE で**光が滑って移る**。「信号がスマホ→メーター→スイッチと渡っていく」を、線を1本も引かずに時間で語る
  - C00a: phone op1 / blur無 / glow 188　C00b: phone 0.62・blur1、meter op1・blur無 / glow 664　C01: switch op1 / glow 1178
  - `role` ラベルと caption も担当機器の登場に合わせて出す＝**各機器が登場時に自己紹介する**
- **セルフデモのループ**：`C01` に **AFTER_TIMEOUT 5s → C02** を張った。**5秒触らないと画面が自分で ✓ を押して見せ、結果まで進んでから C01 に戻って待ち直す**。ユーザーが先に押せばそのまま同じ経路に入るので、デモ用と実操作用のフレームを分ける必要がない

**ENT のズレ・拡大とモーダル寸法（2026-08-13 第13ラウンド）**

**use_figma の落とし穴（追加）**
- `clone()` したフレームを `src.y - 1046` のように置くと**既存フレームに重なる**（C00 が A01 に被った）。セクション内の配置は必ず全子要素の y を見てから決める
- 視覚境界の計算で **`x + 0.8676*W` を y に使う凡ミス**をした（floor-bounce が画面外へ）。視覚 bottom は `y + 0.8676*H`


- **プロトタイプの時間トリガーは `AFTER_TIMEOUT`**（`AFTER_DELAY` ではない）。フィールド名は `timeout`（秒）。`ON_CLICK|ON_HOVER|ON_PRESS|ON_DRAG|ON_MEDIA_END|AFTER_TIMEOUT|MOUSE_*|ON_KEY_DOWN|ON_MEDIA_HIT` が有効値
- **機器スクリーンの `swapComponent()` 後は「`resize(コンテンツ実寸)` → `rescale(目標/実寸)`」の2段が要る**（meter は 800×480→×0.62、phone は 360×800→×0.4889）。rescale は左上基準なので最後に x/y を戻す
- スイッチの variant プロパティ名は **`方向`**、値は `中立 / 上 / 下 / 左 / 右 / 決定`。`instance.setProperties({'方向':'決定'})`
- **`node.clone()` は複製を `figma.currentPage` 直下に置く。元ノードの親には入らない。** そのまま x/y を入れるとページ座標として解釈され、セクションから遠く離れた場所に飛ぶ（画面上は「消えた」ように見える）。必ず `parent.appendChild(clone)` してから x/y を設定する
- クローンは `reactions` も引き継ぐ。用途が違うボタンを複製したら `await node.setReactionsAsync([])` で必ず消す
- `textAlignHorizontal` の変更にもフォントのロードが要る（`characters` を触らなくても）
