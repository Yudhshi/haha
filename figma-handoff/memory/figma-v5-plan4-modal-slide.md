## 第3次改修（同日）— 回弹の作り直し と 質感

**回弹：instance override では動かない（第2次の失敗の原因）**

→ 正解は **component の variant 側に置く**。ただし元セット `1942:20365`（ローカル・6 variant）に直接置くと案②や旧ページの多数のインスタンスまで自動復帰し始めるので、**複製して案④専用にした**：
- **`2831:22068`「HB Switch / Unit · 咪猫版（✓刻印）· 自動復帰［案④専用］」**（Work space、元の右 +240）
- 傾き 5 variant（上 `22099` / 下 `22129` / 左 `22159` / 右 `22189` / 決定 `22219`）に
  `AFTER_TIMEOUT 0.45s → CHANGE_TO 中立(2831:22069) / SMART_ANIMATE / EASE_OUT_BACK / 0.7s`
- **中立は reaction 0 ＝ 終端**（ループ防止）
- 案④ の 20 インスタンスを `swapComponent()` で差し替え。**swap 後に w/h と x/y を復元**（PC 330 / SP 214）
- **監査の落とし穴**：swap 後に `instance.reactions.length` が 1 になるのは override の残存ではなく**コンポーネントからの継承**。`actions[0].destinationId` が `2831:22069`（複製の中立）なら継承、`1942:20366` なら残存。判別はこれで
- **未検証**：プロトタイプ再生はこの環境から動かせない

**質感（「塑料っぽい」への対処）— 全 20 枚に適用**

## 第10次（2026-09-16）— 光と奥行きで「近未来」を出す（グラフィックを足さない方向）

全 36 枚に適用。**判断軸：近未来をグラフィック（グリッド／スキャンライン／等幅の英字）で出すと SF の小道具になり「実在する Honda の製品」という信憑性が落ちる。光と奥行きで出せば製品写真の延長になる。**

1. **画面の光が環境に漏れる（bounce light）** — `amb · 画面の光 / meter`・`/ phone`。機器の**直下の層**に放射グラデの楕円を敷く。サイズは機器基準で `w = dev.w × 1.45(phone 1.90)`／`h = dev.h × 0.72(phone 0.50)`、位置は `y = devBottom − h×0.45`（45% が機器に重なる）。白 `0.065 → 0.038×(55%) → 0`（SP 0.060／phone 0.050・0.045）。**実測でメーター下が RGB +10 明るくなった**。以前ボタンに入れた bloom（14%・狭い輪）が見えなかったのは**狭すぎた**から。バウンスは**広く薄く**が正解
2. **被写界深度**：`phone` にだけ `LAYER_BLUR r0.8`（SP 0.5）。メーターをピント面に残す。0.8px は意識されないが脳は奥行きとして読む
3. **パネルの厚み**：modal/card に `INNER_SHADOW #FFFFFF@0.20 (0,1) r0`（SP 0.18）
4. **リムを斜めに**：縁のグラデを縦 → **斜め**。`gradientTransform = [[0.25,0.75,0],[-0.75,0.25,0.75]]`
   **gradientTransform の意味（重要）**：これは**オブジェクト → グラデーション空間**の写像で、`gx = a*ox + b*oy + tx` がそのままグラデーション位置になる。縦（上→下）の `[[0,1,0],[-1,0,1]]` は `gx = oy` を意味する。任意方向は `a,b` を直接決めればよい（2 行目は `[-b, a, b]` の形に合わせる）

## 第11次（2026-09-16）— 「筐体が樹脂っぽい」の解消＝金属の作り方

## 27. 余白問題の最終解（3条件の同時成立）

**3 条件**＝①左右余白が等しい ②機器間の隙間が等しい ③メーターがモーダル中央。
導出：左右余白が等しい前提だと **`右の隙間 − 左の隙間 = スティック幅 − スマホ幅`**。
→ ③を保ったまま②を満たすには **両脇の可視幅を同じにするしかない**（メーター幅は無関係）。

**スマホ幅の上限は「帯の高さ」で決まる**：画面は 360×800（比 2.222）。
PC ではスマホ下端 489・キャプション下端 109 なので、上端 ≥ 130 とすると
`489 − 2.222W ≥ 130` → **W ≤ 161**。よって **両脇 = 160**（メーター 492 に対する比で算出：`round(meter.width*160/492)`）。

**適用値（21 枚）**
- PC（モーダル 1200）：両脇 160 / 隙間 146 / 余白 48・48 / メーター中心 600＝モーダル中心
  boss `48..208` / meter `354..846` / phone `992..1152`
- 1280（モーダル 1120）：両脇 160 / 隙間 106 / メーター中心 560
- TAB 横（モーダル 944・meter 440）：両脇 143 / 隙間 61 / メーター中心 472
- スティックは **上下中心をメーターの中心軸に一致**（PC で軸 336、boss 256..416）。
  スマホは下端 489 のまま（上端 134）。
- SP / TAB 縦は 2 段組で 3 台横並びではないため対象外（余白は既に左右対称）。

**代償**：スティックが 242.6 → 160（66%）。スマホは 140 → 160 で可読性は上がったが、
明るいスマホに対して暗いスティックが軽く見える。**これ以上スティックを大きくするには
③メーター中央を捨てるしかない**（捨てれば 242.6 のまま隙間均等＝§22 の案A に戻る）。

**補足**：`2943:59093`（旧・余白B / 両脇155）は本実装に吸収されたので役目終了。

## 30. 「次へが変」の正体と、響応式の全面監査

**原因（実測）**：§28 で 次へ だけ 44px にしたため、**戻る 39 / 次へ 44** で高さが不一致。
