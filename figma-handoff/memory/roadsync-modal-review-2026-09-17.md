## 質感の実測（2026-09-18・未実施のリストのみ）

`shots/pc_05.png` / `sp_02.png` を numpy で実測。**数値上で成立していない 9 件**：
1. **パネルの透過ゼロ**：外 (116,111,100) → 縁 1px 内 (26,28,31)。a0.82 なら ≈41 のはず。スクリム #000@42＋progressive blur が背景を殺している。**ガラスの本体が効いていない**

4. **グレイン 4/255**（平坦部 stddev 4.08）＝紙/塗装の記号。Apple の素材にグレインは無い
5. **角の光が +2 RGB** で知覚以下（過去に「シミ」と言われ薄めすぎた）
6. **色温度の割れ**：パネル B−R = PC +8 / SP +11、メーター地は (38,38,38) 無彩色

8. ボタンだけ完全フラット（PH1 準拠の副作用）
9. 影の距離が 1 種類＝3 台が同じ床

**方向 6 つ**：A 面は引き算（グレイン除去・透過を実際に働かせる・リムを四辺へ）／B 光だけ足す（画面の bloom・バウンスに画面の色を拾わせる・出現時の鏡面スイープ）／C 奥行きを 3 層（背景/ステージ/クローム で blur・影・彩度を段に）／D 床をつくる（影＝短く濃く、光＝広く薄く、薄い映り込み）／E 角丸 r28→32〜36 と同心規則／F 文字（36 と 11 の間に中間段が無い、数字が Montserrat と Noto の 2 種）

**整理**：Apple＝引き算、近未来＝光の足し算。両立線は「面から減らし、光だけ足す」。**着手順は 1 → 4 → 3 → 7**。

### 摇杆（HB Switch）の Light 版 — 確定値
**原則：筐体は light、バックライトの皿だけ dark。** LED は暗い窪みが無いと光って見えない。

**全部インスタンスのオーバーライドで行う**（main component を触ると Dark 版が壊れる）。
```

                真っ黒だと「穴」に見える。ただし +10 まで。それ以上上げるとリングが 3:1 を切る

                ← cap(75) がリング内側を覆うので、見えるのは r≥0.688 の環だけ。

                  より多くの絶対輝度を要る＝明テーマでも alpha は下げず上げる

cap    stroke : LINEAR rgb(214,220,230) a0.55 → rgb(150,158,170) a0.18 → rgb(8,10,13) a0.55
```

### 反証で潰れた案
- **全部 light（皿も light）**：シアンが皿に対して 1.0:1 になり、押下キーの信号が消える。
  信号を濃紺 rgb(0,71,106) に落とすと 3:1 は通るが、**✓ は全状態で同じ静的な刻印なので状態を運べない**。
  結果「どのキーが光っているか分からないスイッチ」になる ＝「ここで操作する」の否定。
- **完全な明度ミラー**：cap 下端のストロークが cap と well の分離を 1.46:1 → 1.04:1 に**破壊**する
  （ストロークを消した方が 40% マシ）。cap が三日月に見える。
- 明るい地では**リムハイライトが構造的に効かない**：Dark の上端リムは 11.83:1、Light では純白でも上限 1.59:1。
