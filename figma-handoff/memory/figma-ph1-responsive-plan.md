### セーフエリア移動の副作用：ライダー切り抜きによる遮蔽（2026-09-14 追記）

**UI を 16px 内側へ動かすと gen1/gen2 のメーターカードがライダーに food われる。** 原因は、写真の**切り抜きレイヤーがカードより上の z 順**にあること（gen2 Dark は `Visual` 直下の2枚目の RECTANGLE、gen2 Light は フレーム直下）。カードだけ右に動かすとライダーは動かないので、遮蔽が 16px 増える。実害＝gen2 は目的地ピン・ズーム＋・ルート上部が消え、gen1 は緑ナビタイルの矢印と「16 min」が完全に消える。
- **対策＝写真レイヤー（背景＋切り抜きの2枚）をカードと同じだけ動かす**。これで UI と被写体の関係が元通りになる。
- **動かせる量は写真のはみ出し量（slack）次第**。実測：gen1 は t=-145 で上に 145px の余裕 → **+16,+16 で完全復元**。gen2 は **t=0 でぴったり＝下に動かせない**（動かすと上端 16px にフレームのグラデが出る）→ **+16,+0 のみ**。
- gen2 の残存＝**目的地ピンだけが肩に隠れる**（縦 16px 分）。それ以外（ルート・現在地矢印・60標識・IC・ズーム）は復元済み。
- **失敗した代案**：カード内の `Map` フレーム（clipsContent=true）の中身を 16 上へパン → ピンは戻るが**「60」標識が上端で切れ、ルートの赤/橙区間が消える**ので純損。revert 済み。
- **写真の fill は `scaleMode: FILL`** なので `imageTransform` によるパンは効かない（CROP でないと無効）。リサイズも FILL は中心基準でスケールするため平行移動にならない。
- z順を入れ替えて**カードを切り抜きより上に出すのは却下**：カードの右上がヘルメットに重なるため「頭を UI で隠さない」の原則に反する。

### フォント置換は plugin API では戻せない（2026-09-14・重要）

**存在しないフォントには戻せない。** `node.fontName = {family:'Avenir Next', ...}` は `Cannot use unloaded font` で必ず失敗し、`loadFontAsync` も `font family does not exist` で失敗する。**つまり「環境に無いフォント → 有るフォント」への置換は片道切符**。元に戻す手段は Figma の**バージョン履歴からの復元のみ**（クライアント操作）。
- **教訓：環境に無いフォントを置換する前に、必ず「戻せない」ことを伝えて合意を取る。** 影響ノード数だけでなく不可逆である点を先に言う。
- 今回の置換範囲：PC `2351:21210` / SP `2351:22520` / TAB `2377:22263` / 差し替え用 `2766:21699` / 安全区版 `2776:21945` の計 **448ノード**。
- 対照的に**座標・visible・マスク・写真位置は全部戻せる**。ユーザー要請で安全区版を初期状態へ復元した実績：gen2 写真 x=-287、gen1 写真 -165/-145、Map 子 y=0,0,3,5、ガイド visible=true、セーフエリア違反 0。
