## 0. 最初にやること

1. この CLAUDE.md と `docs/02_figma-map.md`・`docs/06_open-items.md` を読む。

## 3. 進め方（ユーザーが評価している型）

- **小さく作って毎回確かめる**：1 回の `use_figma` で欲張らない。作ったら `screenshot()` か `get_screenshot` で目視。
- **数字で裏を取る**：明るさ・余白・位置ずれは実測して報告する（例：ON-RIDE と OFF-RIDE の平均輝度、原本との画素差分）。やり方は `docs/08_methods.md`。
- **試作は一時コピーで**：本物を何度も書き換えず、画面外（x=-30000 付近）に clone を作って比べ、決めたら本物に適用し、一時コピーは消す。
- **報告は短く・結論から**：何をどこに作ったか、未完了と、ユーザーが決めること。主観の飾りは要らない。
- 解釈が分かれる依頼は、どう解釈したかを報告に一行書く（例：「押した後の情報量」をどう読んだか）。
- ユーザーは自分で section 名を消したり並べ替えたりする。**勝手に名前を戻さない**。

## 4. デザインの原則（このプロジェクトで決まっていること）

- 「使い方」モーダルでは **強調色（青の塗り）は「前へ進む」1 つだけ**（次へ・見てみる）。戻る・最初から・無効は灰。進捗は単色で、現在の手の点だけ次へと同じ青。
- 序章・説明は飾らない（装飾線・チェック一覧・余計な文言を足さない）。
- 押せるもの＝面・縁・影を持つ／押せないもの（手把の上下左右の矢印）＝**線の印刷だけ**。矢印を光らせない。動くのは中央のスティックの頭だけ。
- 手把（スイッチ）の色は **Gen2 の建模（`switch · Gen2` の画像）** に寄せる。ただし建模の画像をそのまま使わない。左の機能切り替えボタンは描かない。
- 比較・入口の案は **UX 4 軸**（気づく／わかる／ジャマしない／迷わない）で評価し、短い口語のカードで書く（`docs/08_methods.md`）。
- 余計な説明文を canvas に増やさない。ラベルは frame 名で足りるならそれで。
- ユーザーは Figma の編集のたびに確認を求めない（「不要问我」）。編集範囲内なら確認せずに進めて、結果を報告する。

## 5. やってはいけないこと

- 編集範囲外のページ・参考資料への書き込み。
- ライブラリの公開／更新の受け入れ。
- ユーザーの frame（例：「ボタン位置」section の案 1〜5 の画）を動かす・作り直す。足すのはカードなど自分のものだけ。
- 確認なしの大量削除。消すのは自分が作った一時物と、ユーザーが「消して」と言ったものだけ。
- `use_figma` で失敗したら同じ台本をそのまま再実行しない。エラーを読んで直す（失敗した台本は何も反映されない＝原子的）。

## 6. 手作業が必要なこと（API でできない）

- **プロトタイプの「スクロール時の位置 = Sticky」は Plugin API で設定も読み取りもできない**（`numberOfFixedChildren` だけ）。案11 の原型の rail（`5641:20394`）はユーザーが手で Sticky にした。作り直すときはユーザーに頼む。
- プロトタイプのデバイス設定（画面の高さ）も API から見えない。原型の rail は「画面の高さ＝720」を前提にしている。
